## Findings

- **Big model dominates.** gpt-5.4 mean score across 4 scenarios: **0.92** vs gpt-5.4-mini: **0.71**.
- **Baseline does not differentiate** — both models hit ~0.83 mean, constrained by iperf3 measurement noise around the 600 Mbps threshold rather than agent skill.
- **Demoted differentiates on planning efficiency.** Mini consistently fails (action_count: 0 in calibration — it ran out of message budget in the 30-message limit before taking an action). Big succeeds when it picks `apply_upf_qos_config` as the fix; one supplemental run (epoch 2) misdiagnosed and used mongo subscriber edits instead, destroying throughput (3.7 Mbps).
- **Lossy differentiates on diagnostic correctness.** Mini's calibration run applied an incorrect QoS config that depressed control-UE latency to 64 ms; the supplement run got it right. Big handles it consistently.
- **Misrouted differentiates on detail accuracy.** Mini calibration used the wrong IMSI (`...002` instead of `...001`), corrupting the subscriber DB further and leaving the UE without an interface (connectivity-fail score = 0). Mini's second epoch got the IMSI right and recovered. Big handled both epochs cleanly.

## Known limitations / caveats

- **Only 2 epochs.** Variance estimates are wide; misdiagnosis rates and IMSI-confusion rates are point estimates, not population means.
- **Throughput threshold is at the iperf3 noise floor.** Sequential iperf3 measurements on this sandbox vary by ±~80 Mbps run-to-run; the 600 Mbps threshold is right at the edge of the achievable ceiling. Even successful agent recoveries occasionally land at 540–590 Mbps and score as throughput-fail. This is measurement validity rather than agent quality.
- **Background-UE metrics are not exported to .eval logs.** The scorer only reads CSVs for UEs that appear in `intent.objectives`, so curves for `ue_background` are unavailable post-hoc despite the metrics-collector running on that container.
- **Parallel runs corrupt throughput data.** Running 2 sandboxes concurrently drops measured throughput by ~20% (root cause undetermined: candidate factors are Docker Desktop VM virtio-net throughput, Linux bridge contention, or macOS thermal effects — CPU and memory headroom were sufficient). All scored data here is from `--max-sandboxes 1`.
- **One supplemental epoch per (model, scenario).** Epoch 1 = smoke (gpt-5.4) / calibration (gpt-5.4-mini); epoch 2 = fresh sequential supplemental run today. Epoch 1 was originally captured for harness debugging; we reuse it as a clean run because it passed the same fixes.
